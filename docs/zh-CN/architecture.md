# 运行架构

[开发指南](development.md) · [团队使用](usage.md) · [English](../en/architecture.md)

TeamSwarm 由 React 界面、本地 Node.js 服务和 Electron 桌面外壳组成。桌面与浏览器客户端使用同一产品 API 和持久状态。

`teamswarm/src/` 渲染对话、协作、执行设置、项目历史和成果；`apps/server/src/` 管理控制 API、项目记录与原生执行；`apps/desktop/` 管理窗口、服务生命周期、目录选择与系统凭据桥接；`packages/contracts/` 保存共享类型。

Host 是用户与 Team 的持续对话入口。成员承担工作，并使用独立原生会话。Work 表示一项责任，Attempt 表示一次绑定实际配置和原生身份的执行。运行状态分别记录排队、执行、停止、恢复与完成。

## 交付与历史

成果具有稳定身份和内容版本，提交、检查和接受针对具体版本。项目文档及历史节点保存有效定义和本地文件快照。从历史创建新分支时保留来源，并形成独立工作上下文。

## Harness 边界

适配器将执行配置转换为原生 Harness 设置，并观察事件、工具调用、会话身份和终态。具有作用域的 Team 工具提供项目上下文、要求、工作、交流、提交和审查接口。模型凭据按选定连接传入，原生会话只有在能力及配置兼容时才恢复。

## 持久化与恢复

SQLite 保存产品事实和执行收据。原生执行启动前记录派发意图；结果未知时保留责任占用，直到恢复完成核对。进程创建身份和系统启动信息用于区分当前执行、复用的 PID 与上次系统启动中的执行。

服务面向本地单用户。界面使用本地控制凭据，代理使用另行限定作用域的 Team 能力。原生工具按照配置权限及当前系统用户权限执行。

当来源消息的 ID 和完整正文与当前工作携带的请求一致时，Host 会从近期历史输入中省略该消息。普通对话使用最近 24 条消息，工作协调使用最近 8 条消息；窗口先选定再省略当前请求，较早轮次中相同文字的消息仍保留。
