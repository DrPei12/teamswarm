# 故障排查

[Harness 配置](harnesses.md) · [数据恢复](data-and-privacy.md) · [English](../en/troubleshooting.md)

| 现象 | 处理方法 |
|---|---|
| Harness 未安装 | 在执行设置安装所选工具。额外 npm 工具需要可用的本机 Node/npm，全局安装目录应位于项目之外。 |
| 账号或凭据不可用 | 重新连接对应 Harness 的账号，或检查资源引用的环境变量名与启动环境。 |
| 模型、协议不兼容 | 选择提供方和 Harness 都支持的模型及协议，保存后重新检查状态。 |
| 提供方提示余额不足或限额 | 处理提供方账号限制，待受影响工作的状态收束后继续或重试。 |
| 工作空间无法启动 | 关闭重复实例，检查端口和诊断信息，排查期间保留数据目录。 |
| Windows 桌面程序在显示窗口前退出 | 使用默认应用安装目录。展开的构建包可尝试较短目录，并在问题报告中附上两种路径。 |
| 工作需要恢复 | 使用恢复功能核对原生执行；确认旧进程已结束后再重试有冲突的工作。 |
| Linux 无法保存 API Key | 在桌面会话中解锁 GNOME Keyring/KWallet；源码服务可使用环境变量引用。 |
| 桌面应用提示浏览器服务正在使用工作空间 | 停止该浏览器/源码服务，再打开桌面应用，以便使用系统密钥环保存凭据。 |
| 更换账号或设备后已保存的 Key 不可用 | 应用会保留加密记录并启动。解锁原密钥环、配置环境变量引用，或在当前设备重新保存 Key。 |
| AppImage 无法挂载 | 安装发行版的 FUSE 支持，或在支持的 Debian/Ubuntu 桌面使用 DEB 包。 |
| Electron 沙箱错误 | 使用支持的安装包和系统安全配置。正常使用时保持沙箱开启，报告系统、包版本与准确错误。 |
| 升级后未找到文件 | 检查系统账号、`TEAM_DATA_DIR` 和项目目录是否一致；必要时将备份恢复到新目录。 |

报告问题时提供应用版本、系统与架构、Harness 版本、最小复现步骤和准确错误。按[数据与隐私](data-and-privacy.md)导出诊断，检查内容并去除私有信息后再上传。

单一系统上的启动问题还应说明从桌面还是终端启动。源码用户补充 `node --version` 和实际执行的命令。
